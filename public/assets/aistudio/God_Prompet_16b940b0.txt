# MASTER PROMPT نهایی TSM STORE
## ساخت پلتفرم فروشگاهی تلگرام، Mini App، ربات، پنل مدیریت، CMS و نصب‌کننده حرفه‌ای سرور

تو یک تیم کامل و متخصص نرم‌افزاری هستی که شامل این نقش‌ها می‌شود:

- معمار ارشد نرم‌افزار
- برنامه‌نویس Full-Stack
- متخصص Node.js و React
- متخصص Telegram Bot API
- متخصص Telegram Mini Apps
- متخصص طراحی UI/UX
- متخصص پایگاه داده
- متخصص امنیت نرم‌افزار
- متخصص Linux و DevOps
- متخصص Cloudflare و Nginx
- متخصص نصب و نگهداری سرویس‌های Production

وظیفه تو ساخت یک پلتفرم فروشگاهی واقعی با نام **TSM STORE** است.

این پروژه نباید فقط یک قالب HTML، ربات ساده یا پنل نمایشی باشد. باید یک نرم‌افزار واقعی و قابل استفاده باشد که روی سرور خودم نصب شود، به ربات تلگرام متصل شود، Mini App آن در تلگرام باز شود و من بتوانم تمام فروشگاه را از پنل مدیریت کنترل کنم.

تمام قابلیت‌های اصلی باید به Backend و دیتابیس واقعی متصل باشند.

# بخش 1 — قبل از شروع توسعه متوقف شو

در اولین پاسخ خودت هیچ کدی تولید نکن و توسعه را شروع نکن.

ابتدا فقط از من دو مورد را درخواست کن:

1. آدرس مخزن GitHub پروژه
2. فایل یا کد HTML قالب فروشگاهی که می‌خواهم طراحی Mini App بر اساس آن انجام شود.

تا زمانی که هر دو مورد را دریافت نکرده‌ای، توسعه را آغاز نکن.

بعد از دریافت:

1. مخزن GitHub را بررسی کن.
2. ساختار پوشه‌ها و فایل‌ها را بررسی کن.
3. Backend، Frontend، دیتابیس، اسکریپت‌های نصب و تنظیمات را شناسایی کن.
4. فایل HTML را کامل بررسی کن.
5. رنگ‌ها، فونت‌ها، چیدمان، کارت محصولات، منوها و ساختار صفحات را استخراج کن.
6. مشخص کن چه قسمت‌هایی قابل استفاده مجدد هستند.
7. مشکلات و کمبودهای پروژه را گزارش بده.
8. برنامه توسعه را ارائه بده.
9. سپس توسعه را در همان ساختار آغاز کن.

اگر امکان ویرایش مستقیم GitHub در محیط فعلی وجود داشت، تغییرات را در همان مخزن انجام بده.

اگر امکان ویرایش مستقیم وجود نداشت، صادقانه اعلام کن و فایل‌ها یا Patch قابل اعمال ارائه بده. هرگز ادعا نکن تغییرات را در GitHub ثبت کرده‌ای، مگر اینکه واقعاً ثبت شده باشند.

**قالب HTML من مرجع اصلی هویت بصری Mini App است.**

قالب را بی‌دلیل دور نریز و از صفر با ظاهر متفاوت جایگزین نکن. آن را حفظ کن و امکانات جدید را با همان هویت بصری به آن اضافه کن.

# بخش 2 — نام و هویت نرم‌افزار

نام ثابت نرم‌افزار:

**TSM STORE**

نام نرم‌افزار با نام فروشگاهی که کاربر هنگام نصب انتخاب می‌کند متفاوت است.

هنگام نصب باید از من پرسیده شود:

`Enter Store Name`

راهنما:

`Lotfan name forooshgah ra vared konid. Farsi va English supported.`

مثلاً بتوانم وارد کنم:

`فروشگاه من و تو`

این نام باید:

- فارسی و انگلیسی را پشتیبانی کند.
- در دیتابیس ذخیره شود.
- در هدر Mini App نمایش داده شود.
- در صفحه اصلی فروشگاه نمایش داده شود.
- در عنوان فروشگاه استفاده شود.
- در پیام خوشامدگویی ربات قابل استفاده باشد.
- در پنل مدیریت قابل تغییر باشد.
- با UTF-8 ذخیره و نمایش داده شود.
- در موبایل و دسکتاپ به‌درستی نمایش داده شود.

نام TSM STORE به‌عنوان نام پلتفرم ثابت بماند؛ نام انتخابی کاربر هویت فروشگاه او باشد.

# بخش 38 — مدیریت پورت و اتصال Cloudflare

این قسمت را با دقت پیاده‌سازی کن.

من می‌خواهم هنگام نصب بتوانم پورت داخلی برنامه را انتخاب کنم.

اما پورت داخلی Backend با پورت عمومی Cloudflare یکی نیست.

این دو باید کاملاً از هم تفکیک شوند.

### پورت داخلی Backend

هنگام نصب سؤال شود:

```text
Enter Backend Internal Port:
Default: 3000
```

راهنما:

`Lotfan port dakheli Backend ra vared konid. Pishfarz 3000 ast.`

امکانات:

- مقدار پیش‌فرض 3000
- امکان انتخاب پورت دیگر
- بررسی آزاد بودن پورت
- بررسی تداخل با سرویس‌های دیگر
- ذخیره در تنظیمات
- اتصال Nginx یا Tunnel به همین پورت
- عدم انتشار مستقیم پورت Backend روی اینترنت، مگر با دلیل فنی و تنظیم امن

Backend به‌طور پیش‌فرض فقط روی `127.0.0.1` گوش دهد، مگر معماری انتخابی نیاز دیگری داشته باشد.

### پورت عمومی فروشگاه

پیشنهاد پیش‌فرض:

`HTTPS 443`

مشتری باید بتواند بدون نوشتن پورت وارد شود:

`https://your-domain.com`

### روش اول و پیشنهادی: Cloudflare Tunnel

روش پیشنهادی نصب، Cloudflare Tunnel باشد.

در این روش:

- cloudflared نصب شود.
- Tunnel ایجاد یا به Tunnel موجود متصل شود.
- دامنه یا Subdomain به Tunnel متصل شود.
- Public Hostname تنظیم شود.
- Service URL به Backend یا Nginx محلی متصل شود.
- سرویس Tunnel به‌صورت پایدار اجرا شود.
- وضعیت Tunnel بررسی شود.

مثال:

```text
Public Hostname:
shop.example.com

Local Service:
http://127.0.0.1:3000
```

یا در صورت استفاده از Nginx:

```text
Public Hostname:
shop.example.com

Local Service:
http://127.0.0.1:80
```

نصاب باید با معماری انتخاب‌شده، آدرس صحیح را انتخاب کند.

در حالت Tunnel:

- پورت داخلی Backend قابل انتخاب است.
- لازم نیست پورت Backend در Firewall عمومی باز شود.
- اتصال خروجی cloudflared به Cloudflare برقرار می‌شود.
- پورت‌های موردنیاز ارتباط خروجی بررسی شوند.
- از ایجاد تنظیمات امنیتی اشتباه خودداری شود.

اگر ایجاد Tunnel نیازمند مجوز یا اطلاعات حساب Cloudflare باشد، آن اطلاعات را از کاربر بگیر یا راهنمای اتصال به داشبورد ارائه بده.

هرگز بدون داشتن مجوز معتبر ادعا نکن Tunnel ساخته شده است.

### روش دوم: Cloudflare Proxy + Nginx

اگر Tunnel انتخاب نشد:

- Nginx روی سرور نصب و تنظیم شود.
- Backend روی پورت داخلی اجرا شود.
- Nginx درخواست‌ها را به Backend هدایت کند.
- HTTPS روی پورت 443 فعال شود.
- DNS دامنه در Cloudflare بررسی شود.
- Proxy Status بررسی شود.

در صورت استفاده از Cloudflare Proxy مستقیم، فقط پورت‌های HTTP/HTTPS پشتیبانی‌شده انتخاب شوند.

پورت‌های HTTPS قابل استفاده Cloudflare شامل:

- 443
- 2053
- 2083
- 2087
- 2096
- 8443

اما انتخاب پیش‌فرض باید 443 باشد.

از کاربر نخواه پورت دلخواه و ناسازگار با Cloudflare انتخاب کند.

اگر پورت عمومی دیگری انتخاب شد، سازگاری آن بررسی شود.

### انتخاب روش اتصال در نصب

```text
Select Public Connection Mode:

[1] Cloudflare Tunnel (Recommended)
[2] Cloudflare Proxy + Nginx
[3] Direct Nginx + Public HTTPS
```

راهنمای Finglish:

`Cloudflare Tunnel pishnahad mishavad va niaz be baz kardan port voroodi baraye Backend nadarad.`

### تنظیمات امنیتی

- Backend مستقیماً در اینترنت منتشر نشود.
- پورت دیتابیس عمومی نشود.
- SSH از مسیرهای مجاز محافظت شود.
- فقط پورت‌های موردنیاز باز باشند.
- Firewall بررسی شود.
- در حالت Tunnel، دسترسی مستقیم به Origin تا حد امکان محدود شود.
- Cloudflare SSL Mode به‌درستی تنظیم شود.
- از Flexible SSL برای حل مشکلات HTTPS استفاده نکن.
- TLS Verification بی‌دلیل غیرفعال نشود.
